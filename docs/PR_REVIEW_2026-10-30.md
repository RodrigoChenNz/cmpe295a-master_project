## PR #5 — E-ink and gateway lora

Recommendation: request changes before integrating the physical acknowledgement path.

1. **P1 — upgrade existing databases without deleting their data.** `infra/postgres/02-shelfiq.sql:176` introduces `device_id`, and `app/main.py:58–82` refuses to start without new tables/columns and tells users to recreate the database. PostgreSQL initialization scripts do not run again on an existing volume. A normal upgrade therefore stops the API unless the store deletes its data or writes its own SQL. Add an additive migration for device IDs, discoveries, pairing state and label-event constraints, and test upgrading a populated previous-version database.
2. **P1 — do not attribute an old render to a new decision.** `tools/lora_bridge.py:328–330` keys decision history by a hash of cents and reason. Publishing a different decision with the same price/reason overwrites that history entry; a later check-in with the old hash is returned as the new decision by `shelf_report` (`:469–482`). `app/labels_in.py:105–115` then confirms matching pushes, accepting absent decision IDs as a wildcard. This cannot establish that a new publication or changed display name reached the device. Reproduced by loading the PR's bridge module, publishing two distinct decision IDs with identical price/reason, and calling its report function with the first render hash: the report identifies the second decision as in sync. Carry an ordered publication identity through the radio and acknowledgement, bind it to product/device and intended content, and settle only that publication. Keep legacy price-only sightings as liveness or observed-price reports rather than verified delivery.
3. **P2 — serialize adoption of an existing device-less label.** `app/routers/labels.py:296–310` checks `device_id` and updates it in separate operations. Two editors adopting different devices into the same empty label can both pass the check and succeed; the second update silently replaces the first. A unique device constraint does not prevent this because the device IDs differ. Use a transaction with a row lock or a conditional update `WHERE device_id IS NULL RETURNING ...`, returning 409 when another adoption wins.
